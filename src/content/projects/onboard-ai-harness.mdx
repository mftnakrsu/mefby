## Overview

The harness that will run on the onboard computer of an autonomous vehicle. It starts and feeds two AI modules, one that fuses sensor data into tracked objects and one that proposes what to do next; it watches their timing and health, connects them to the vehicle's control computer and to the operator's station, and records every message. The control computer always has the final say.

## Design

Every proposal passes a safety gate before it reaches the control computer. While the link to the operator is up, the operator approves each proposal; if the link drops, a deterministic policy decides onboard. The system is built in rate layers, and a slow layer never blocks a fast one: consumers keep only the latest state, treat data as stale once it passes its maximum age, and never queue old messages. Events are acknowledged and sent up to six times, which at 5% packet loss leaves about one chance in sixty million that an event is lost.

## Status

Phase 1 runs everything on one computer in simulation, with mock AI modules and a software-in-the-loop simulator in place of the control computer. The first milestone is done: the message contract with its topic registry and a generated reference, UDP transport with a reliable layer, and the staleness helpers.
